개발 하네스

개발의 속도와 보안의 신뢰를 함께 설계하세요. GovCode Harness는 보안 기준을 개발 과정에서 실행할 수 있도록 검사·수정 지원·승인·증적을 연결합니다. 팀이 다음에 할 일과 검토 근거를 같은 흐름에서 확인하는 것이 목표입니다.

개발 흐름 직접 체험하기도입 브로슈어 보기

현재 v0.9.0: 민원 API 로깅을 첫 사례로 검증 · 분야별 확장 설계 중

지향하는 개발 경험 / 기준에서 검증 근거까지

  1. 1프로젝트 조건과 적용 요구 정리적용성
  2. 2규정별 수행 작업·산출물 안내작업
  3. 3자동 검사·수정 지원과 담당자 검토충족
  4. 4승인·예외·증적과 변경 영향 연결추적

하네스는 개발 도구와 정책·검사·승인 절차를 연결하는 실행 기반입니다. 첫 로깅 사례에서 그 연결을 검증했고, 프로젝트별 요구로 확장을 설계하고 있습니다.

첫 사례 320개 회귀 시험 통과실패 0 · 건너뜀 0, 로컬 참조 기준

위험본 deny → 수정본 allow새 commit과 증적을 함께 확인

기관 내부 실행 지향공개 사이트는 안내 자료만 제공

개발하는 순간부터,
보안 기준이 작동하도록.

개발자는 수정할 지점을, 보안 담당자는 판단할 근거를, 프로젝트 책임자는 남은 작업을 알아야 합니다. GovCode Harness는 각자의 업무를 하나의 개발 흐름으로 연결하는 것을 지향합니다.

개발자에게는 다음 행동을

탐지 결과를 수정 지원과 재검사로 이어 갑니다. 첫 로깅 사례에서는 위험 코드의 차단과 수정본의 통과를 확인했습니다. 개발자가 결과를 보고 다음 작업으로 이어 갈 수 있는 흐름입니다.

검토자에게는 판단 근거를

어떤 정책으로 무엇을 검사했고 누가 승인했는지 연결합니다. 첫 사례에서 독립 승인과 서명 증적을 검증했습니다. AI의 수정 제안도 담당자의 승인과 검사를 거칩니다.

책임자에게는 진행의 가시성을

검사·수정·예외 이력을 관리 화면에서 확인합니다. 프로젝트 전체의 충족·미충족·검토 대기·미검증과 다음 작업을 안내하는 기능은 확장 계획에 포함됩니다.

보안에서 시작해,
공공 프로젝트의 요구까지.

프로젝트 프로필로 적용 조건을 정리하고, 분야별 규정 팩으로 필요한 작업·검사·산출물을 연결하는 방향입니다. 아래 분야는 확장 후보이며 적용 여부는 프로젝트별로 확인합니다.

개인정보·보안 / 접근성

보호 요구와 이용 환경별 점검을 작업·수정·검토 근거에 연결하는 방향입니다.

개발 품질 / 표준·상호운용성

필수 시험과 프로젝트별 개발·인터페이스 기준을 확인하도록 확장합니다.

사업 산출물 / 운영·보존

단계별 문서·검수·운영·보존 요구와 제출 근거를 안내하도록 확장합니다.

개인정보 로깅으로 먼저 체험하세요 합성 민원 API에서 위험 탐지 → 차단 → 수정 → 새 commit 재검사 → 통과 → 증적을 확인할 수 있습니다. 보안 기준이 개발 과정에서 어떻게 작동하는지 보여 주는 첫 사례입니다. 다른 분야는 별도 구현·검증이 필요합니다.

개발과 검토가
같은 근거로 이어집니다.

개발팀과 검토 담당자는 역할에 맞는 권한으로 정책·실행·증적을 확인합니다. 한국어 관리 화면에서 수정·재검사·예외 이력을 따라갈 수 있습니다.

  • 기관·프로젝트·역할에 따른 서버 측 접근 통제
  • 합성 작성자·승인자·운영자·감사 열람자 역할
  • 보관 잠금과 백업·복구를 포함한 증적 수명주기

화면은 합성 감사 열람자로 검증한 예시입니다. 실제 기관 신원 연동은 별도 적용이 필요합니다.

첫 도입은 작게.
다음 결정은 근거 있게.

합성 데모로 개발 흐름을 체험하고, 승인된 한정 저장소에서 적용 가능성을 살펴보세요. 팀의 개발 환경과 검토 절차에 맞는지 확인한 뒤 도입 범위를 정할 수 있습니다.

지금 실행할 수 있는 것

탐지·게이트·독립 승인·서명 증적·보관 및 복구·관리 API와 화면·승인된 수정의 격리 검증을 로컬에서 확인할 수 있습니다.

도입 전에 확정할 것

기관별 규정 적용, 운영 신원·키, 보존 분류, 실제 CI 연결, 모델 사용·반출 범위와 파일럿 책임자를 결정해야 합니다.

지원 경계 현재 분석은 제한된 Python AST 범위입니다. 전체 수정 격리 검증은 macOS에서 확인했습니다. 참조 데모의 모델은 fixture이며 실제 LLM 추론·품질을 검증한 결과가 아닙니다.
