PR 보도자료 초안

작성일: 2026-10-30 · 제품 방향 검토용 초안 · 원문과 변경 이력

실제 출시 공지가 아닙니다. 목표 출시 시점의 고객 경험을 그린 문서입니다. 인용문은 가상 발언이며 정식 출시일은 미정입니다. 현재 제공 기능은 고객 FAQ 1번과 공개 버전 안내에서 확인하세요.

GovCode Harness 비개발자의 공공 업무 도구 제작에 보안 점검과 승인 절차를 연결

보안이 내재화된 개발 하네스. 업무를 아는 사람이 AI와 함께 도구를 만들고, 필요한 점검과 검토를 거쳐 활용합니다.

GovCode Harness는 다양한 공공 프로젝트에서 비개발자가 안전하게 바이브 코딩을 하도록 돕는 오픈소스 개발 하네스를 공개했습니다. 사용자는 만들고 싶은 업무 도구를 자연어로 설명하고, AI가 만든 결과를 시험하며 수정합니다. 하네스는 프로젝트별 기준과 허용 범위를 제작 과정에 연결하고, 점검 결과와 검토가 필요한 이유를 사용자가 이해할 수 있게 안내합니다.

공공 업무 담당자는 반복되는 자료 정리나 보고, 현황 조회에 어떤 도구가 필요한지 잘 압니다. 그러나 AI가 작성한 코드가 어떤 자료에 접근하고 무엇을 바꾸는지, 실제 업무에 사용해도 되는지까지 판단하기는 어렵습니다. 도구를 만들 수 있다는 가능성과 책임 있게 사용할 수 있다는 확신 사이에 간격이 있습니다. GovCode Harness는 사용자가 제작을 이어 가면서도 그 간격을 확인하고 필요한 검토를 받을 수 있도록 돕습니다.

사용자는 먼저 업무 목적과 사용할 자료, 대상 사용자를 설명합니다. 하네스는 필요한 확인 사항을 정리하고, AI의 코드 생성·수정과 실행에 점검 절차를 연결합니다. 사용자는 허용된 환경에서 결과를 살펴보고 수정 요청을 이어 갑니다. 문제가 발견되면 무엇이 잘못됐는지와 다음에 할 일을 안내받습니다. 담당자 판단이 필요한 항목은 검토로 연결하고, 변경·검사·승인 기록은 해당 결과에 함께 남깁니다.

“업무를 아는 사람이 직접 도구를 만들 수 있어야 합니다. 동시에 코드의 모든 위험을 혼자 판단하지 않아도, 허용된 범위와 필요한 검토를 이해하며 진행할 수 있어야 합니다.”

— 프로젝트 대변인의 가상 발언입니다. 실제 인터뷰가 아닙니다.

예를 들어 자료 정리 도구를 만드는 담당자는 원하는 입력과 보고 형식을 설명하고, 가상 자료로 결과를 확인합니다. 하네스는 확인하지 못한 자료 접근이나 외부 전송을 그대로 완료 처리하지 않고 필요한 검토를 안내합니다. 실제 자료 사용과 공유·운영 반영은 승인된 범위에서 진행합니다. 이 흐름은 민원 처리뿐 아니라 여러 공공 업무 도구에 적용하는 것을 목표로 합니다.

“필요한 보고 도구를 제 말로 설명하고 결과를 바꿔 가며 만들 수 있었습니다. 어디까지 시험해도 되는지, 실제 자료를 쓰기 전에 누구의 확인이 필요한지 알 수 있어 다음 단계로 진행하기 쉬웠습니다.”

— 비개발자 공공 업무 담당자의 가상 발언입니다. 검증할 고객 경험을 표현한 예시입니다.

프로젝트 코드는 Apache-2.0 조건에 따라 라이선스 비용이나 로열티 없이 사용할 수 있습니다. 현재 공개 파일럿은 민원 로깅 사례를 통해 점검·수정·확인 자료 연결의 기반을 체험하는 단계입니다. 관심 있는 사람은 쉬운 안내를 읽고, 직접 만들고 싶은 공공 업무 도구와 제작 과정의 어려움을 참여 안내를 통해 알려 줄 수 있습니다. 설치·인프라·운영 비용은 사용 환경에 따라 발생할 수 있습니다.
