GGovCode Harness

공공 프로젝트 규정을
실행 가능한
업무로 연결합니다.

법령·규칙·가이드라인을 수행 작업과 충족 근거로.
적용 요구부터 자동화·검토·증적까지 안내하는 것이 제품의 목표입니다.

  1. 1프로젝트 조건과 적용 요구 정리적용성
  2. 2규정별 수행 작업·산출물 안내작업
  3. 3자동 검사·수정 지원과 담당자 검토충족
  4. 4승인·예외·증적과 변경 영향 연결추적

작업을 안내합니다

프로젝트의 적용 요구를 수행 작업·산출물·검사에 연결하는 것이 목표입니다.

충족을 지원합니다

자동 검사·수정 지원과 담당자 검토·승인을 연결합니다.

근거를 남깁니다

작업·검사·수정·승인의 이력을 증적으로 추적합니다.

공공 프로젝트의 수행자와 검토자가 같은 요구와 충족 근거를 확인하도록.
기관 내부 실행을 지향하며, AI는 제안만 하고 승인과 판정을 대신하지 않습니다.

목표 흐름을 설명한 자료입니다. 현재 v0.9.0은 민원 API 개인정보 로깅을 첫 사례로 구현했으며, 모든 분야의 규정 자동 충족 기능이 구현된 것은 아닙니다.

첫 사례의 검증과 제품 확장

민원 API 로깅은 첫 사례입니다.
제품의 목표는 공공 프로젝트 전반입니다.

첫 사례의 회귀 시험 320개 통과, 실패 0·건너뜀 0.
로깅 위험 deny → 수정본 allow, 공통 정책·승인·증적·관리 기반을 확인했습니다. 다른 규정 분야의 검증 결과로 일반화하지 않습니다.

새 독립 합성 표본 40건: 지원 위험 16/16 탐지, 지원 안전 오탐 0/16, 지원 검토 필요 1/32, 전체 위험 allow 0건. 실제 기관 코드 성능이나 준수 인증이 아닙니다.

  1. 1

    프로젝트 요구 정리

    법령·규칙·가이드·계약상 기준의 적용 조건과 담당자를 정리합니다.

  2. 2

    수행 작업과 검사 연결

    필요 산출물·자동 검사·수정 지원·담당자 검토·증적을 요구에 연결합니다.

  3. 3

    한 분야씩 검증

    현재 로깅 사례를 실행하고, 추가 규정 분야마다 독립 정답과 성공 기준을 정합니다.

  4. 4

    충족 현황과 변경 영향 관리

    미충족·미검증·검토 대기와 다음 작업을 안내하는 흐름을 후속 설계합니다.

확장 후보 / 분야별 규정 팩은 후속 설계
개인정보·보안, 접근성, 개발 품질, 표준·상호운용성,
사업 수행·산출물, 운영·기록·보존. 적용 여부는 프로젝트별로 확인합니다.

현재 검증: 제한된 Python 로깅 분석·macOS 격리·fixture 모델. 실제 LLM 품질·기관 승인·법령 적용 확정·실데이터 파일럿은 미검증입니다. 법령상 의무와 예시 정책을 구분합니다.
