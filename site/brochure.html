GGovCode Harness

개인정보 로깅 위험을
코드 변경 단계에서
다루세요.

민원 API의 위험 탐지부터 변경 차단, 수정·재검사, 증적 생성까지.
공공부문 도입 검토를 위한 로컬 참조 구현입니다.

  1. 1민원 본문을 로그에 기록하는 코드deny
  2. 2원문 로깅 제거 · 감사 이벤트 유지수정
  3. 3새 commit의 필수 검사 재실행allow
  4. 4정책·판정·수정 이력을 증적으로 연결증적

변경을 검사합니다

새 commit을 검사하고 오류·미분석을 통과로 바꾸지 않습니다.

승인을 분리합니다

정책 작성과 독립 승인, 서명·만료·철회를 연결합니다.

근거를 남깁니다

원문 없는 서명 증적과 수정·검토 이력을 연결합니다.

개발·정책·감사 담당자가 같은 변경의 판단 근거를 확인하도록.
기관 내부 실행을 지향하며, AI는 제안만 하고 승인과 판정을 대신하지 않습니다.

기본 차단 범위는 CI에 연결한 병합·배포 단계입니다. 운영 민원 요청을 차단하는 기능이 아닙니다.

검증 근거와 도입 순서

확인한 결과로 시작하고,
기관의 조건에 맞춰 검증하세요.

전체 회귀 시험 320개 통과, 실패 0·건너뜀 0.
위험본 deny → 수정본 allow, 증적 이동·보관·복구, 역할별 관리 API와 화면을 로컬에서 확인했습니다.

새 독립 합성 표본 40건: 지원 위험 16/16 탐지, 지원 안전 오탐 0/16, 지원 검토 필요 1/32, 전체 위험 allow 0건. 실제 기관 코드 성능이나 준수 인증이 아닙니다.

  1. 1

    합성 자료로 실행

    고정 버전 소스를 받고 기본 데모와 서명 참조 흐름을 확인합니다.

  2. 2

    기관 통제 조건 정의

    규정 적용성, 승인자·키·신원, 증적 보존, 모델 사용·반출 범위를 정합니다.

  3. 3

    한정된 저장소에서 파일럿

    독립 정답과 기간·성공 기준을 합의하고 탐지·오탐·검토 부담을 측정합니다.

  4. 4

    검토 후 CI에 연결

    신뢰한 commit·필수 검사·보호 브랜치를 연결하고 운영 책임을 확정합니다.

현재 지원 범위
제한된 Python AST 분석. 전체 OS 격리 검증은 macOS 기준.
모델은 fixture이며 실제 LLM 추론·품질은 검증하지 않았습니다.

실제 기관 승인·법령 적용 확정·원격 CI 적용·실데이터 파일럿은 미실시입니다. 법령상 의무와 예시 정책을 구분하며 검사 통과를 법적 준수 인증으로 표시하지 않습니다.
