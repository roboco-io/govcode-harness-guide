설치·실행 안내

이 페이지는 개발 도구를 설치하고 명령을 실행하는 담당자를 위한 안내입니다. 프로젝트를 처음 살펴보신다면 설치 없이 읽는 쉬운 안내부터 보세요. 아래 절차는 시험용 민원 프로그램을 점검하는 방법입니다.

처음 시작하는 순서우리 팀의 개발 흐름부터1. 준비와 지원 범위2. 소스 받기3. 기본 흐름 확인4. 전체 참조 실행새 기능: 프로필·규정 팩·문서5. 기존 참조 결과 읽기6. 관리 화면 열기7. CI 적용 준비8. 기관 파일럿 준비문제 해결검증 근거와 자료

파일럿에 참여해 주세요. 본 프로젝트는 Apache-2.0 조건에 따라 라이선스 비용이나 로열티 없이 사용할 수 있습니다. 실행 경험이나 문서 의견은 피드백·기여 안내에서 남겨 주세요.

우리 팀의 개발 흐름부터 살펴보세요

보안이 내재화된 개발 하네스는 팀의 보안 기준을 작업·검사·수정 지원·승인·증적으로 연결하는 실행 기반입니다. GovCode Harness는 이를 공공 프로젝트에 적용하는 것을 지향합니다. 먼저 다음 질문으로 도입 범위를 정리하세요.

  1. 어떤 개발 단계와 저장소에 적용할까요? 프로젝트 유형·기관 조건·적용 후보 기준을 정리합니다.
  2. 개발팀이 무엇을 해야 할까요? 기준의 출처·버전·적용 조건을 확인하고 작업·산출물·담당자를 연결합니다.
  3. 어디까지 자동화할까요? 검사·수정 지원과 담당자 판단·승인의 역할을 정합니다.
  4. 무엇을 완료 근거로 삼을까요? 검사 결과·검토 기록·증적과 다음 작업을 정합니다.

목표와 현재 기능 공개 v0.10.0 프리뷰에 프로젝트 프로필·규정 팩 발행·적용성 판단·설계 문서 초안 생성이 포함됐습니다. 산출물 검사와 전체 충족 현황은 후속 범위입니다. 아래 명령은 이 공개 태그를 기준으로 합니다. 개발 상태와 공개 범위 확인

제품 전체 범위와 다음 설계

1. 준비와 지원 범위

개발자 또는 플랫폼 담당자가 로컬 환경에서 시작할 수 있습니다. 실제 민원 원문·운영 비밀값을 준비할 필요가 없습니다.

경로필요 환경확인하는 것
기본 데모Python 3.10 이상, Git표준 라이브러리 경로의 탐지·차단·수정·재검사. 서명 없음.
전체 참조 데모macOS, Python 3.12 이상, Git, uv, sandbox-exec 사용 가능 환경서명 정책·격리 수정·증적·보관·복구·관리 API. 로컬 HTTP와 프로세스 실행 허용 필요.
패키지 설치최초 의존성 다운로드용 네트워크버전·해시 잠금 의존성을 전용 .runtime 환경에 설치. 전역 Python은 변경하지 않음.

전체 참조 검증 환경은 macOS와 Python 3.12입니다. 다른 OS에서 기본 검사를 시도할 수 있지만, 전체 격리 검증의 지원을 보장하지 않습니다.

환경 도구: Python 공식 다운로드 · uv 공식 설치 안내. 기관에서 승인한 설치 경로를 사용하세요.

2. 고정 버전의 소스 받기

가이드의 기준 소스는 공개 프리릴리스 v0.10.0입니다. 이전 버전에서 사용한 작업 폴더와 구분해 새 폴더에 받으세요. 이미 같은 이름의 폴더가 있다면 새 작업 경로를 사용하세요.

git clone --branch v0.10.0 --depth 1 https://github.com/roboco-io/govcode-harness.git
cd govcode-harness

라이선스 포함 소스 ZIP 다운로드도 가능합니다. 압축을 푼 경우 해당 폴더로 이동하세요. 검사 대상 저장소는 Git commit이 필요하지만, Harness 자체는 ZIP에서 실행할 수도 있습니다.

본 프로젝트와 이 가이드는 독립 저장소입니다. 가이드 수정에 서브모듈 갱신이 필요하지 않습니다. 가이드 소스의 버전 대응표에서 기준 코드를 확인할 수 있습니다.

3. 기본 흐름 먼저 확인하기

프로젝트 루트에서 실행합니다. 명령은 새 합성 Git 저장소와 예시 자료를 출력 폴더 안에 만듭니다. 기존 업무 저장소는 수정하지 않습니다.

python3 -m govcode_harness demo --output .runtime/first-onboarding

정상 완료 시 명령의 종료 코드는 0이며 결과에는 before: deny, after: allow, signature_status: not_signed가 표시됩니다.

응답 보존, 민원 본문의 일반 로그 제거, 필요한 감사 호출 보존을 함께 확인합니다. 이 경로의 증적은 서명된 운영 증적이 아닙니다.

4. 서명과 관리까지 전체 참조 실행하기

전용 환경 설치

아래 두 경로는 설치된 Python 3.12 이상과 uv의 실제 절대 경로로 바꾸세요. command -v python3.12와 command -v uv로 경로를 확인할 수 있습니다.

python3 scripts/setup_reference.py \
  --python /absolute/path/to/python3.12 \
  --uv /absolute/path/to/uv

버전·해시 잠금 파일에 따라 별도 환경을 만들고 정책·UI 자원을 포함한 Harness 패키지를 설치합니다. 기존 환경은 덮어쓰지 않습니다.

새 출력 폴더에 실행

.runtime/reference-venv/bin/python -m govcode_harness reference-demo \
  --output .runtime/onboarding-reference

합성 작성자와 독립 승인자의 키 생성 → 예시 정책 서명 → 위험 commit 차단 → fixture 수정 제안과 승인 → 실제 OS 격리 검사 → 별도 알려진 수정 commit의 통과 → 증적 보관·복구 → 관리 API 확인 순서로 실행합니다.

중요한 구분 격리된 제안 수정의 검사와 별도 알려진 수정 commit의 게이트 통과를 함께 확인하는 참조 흐름입니다. 실제 LLM이 자동으로 코드를 고쳐 운영 배포했다는 뜻이 아닙니다.

v0.10.0 프리뷰의 새 기능 실행하기

위의 전용 환경 설치를 마친 뒤 아래 명령을 각각 실행하세요. 기존 전체 참조 데모 실행은 이 세 명령의 선행 조건이 아닙니다. 출력 폴더는 매번 새 경로를 사용합니다.

사업 정보의 버전과 승인 확인

.runtime/reference-venv/bin/python -m govcode_harness project profile-demo --output .runtime/onboarding-profile

서로 다른 담당자의 승인으로 정보 두 버전을 만들고, 미확정 정보를 유지하며 자기 승인을 거부하는지 확인합니다. 결과 파일 profile-demo-result.json의 active_revision은 2, 확인 항목 6개는 모두 true가 기대 결과입니다.

규정 묶음과 적용 대상 확인

.runtime/reference-venv/bin/python -m govcode_harness project pack-demo --output .runtime/onboarding-pack

서명된 규정 묶음의 발행·버전 고정, 독립 검토, 취소된 자료의 사용 거부를 확인합니다. 확인 항목 7개가 모두 true이고 최종 적용·제외·검토 필요 항목은 2·1·0입니다. 적용 대상 판단 완료는 요구 충족이나 운영 승인을 뜻하지 않습니다.

설계 문서 초안 만들기

.runtime/reference-venv/bin/python -m govcode_harness project document-kit --output .runtime/onboarding-documents

PRD·아키텍처·데이터 모델·규정 추적 매트릭스·ADR·백로그와 AGENTS.md·작성 정책, 별도의 검토 메모를 만듭니다. 정보가 없으면 미제공으로 표시합니다. 생성 성공은 사실 검증이나 문서 승인이 아닙니다. AI Doc Ready를 자동 설치·실행하지 않으며 사실·수치·의미는 원문과 대조해야 합니다.

프로필 상세 안내 · 규정 팩·적용성 안내 · 문서 생성과 선택적 구조 검사

데모 출력에는 시험용 개인 키가 포함될 수 있습니다. 출력 폴더 전체를 공개하지 마세요.

6. 로컬 관리 화면 열기

.runtime/reference-venv/bin/python -m govcode_harness control \
  --config .runtime/onboarding-reference/control-config.json \
  --port 8766

명령이 표시하는 http://127.0.0.1:8766/에 접속합니다. 터미널에서 서버를 실행한 상태로 유지하세요. 새 터미널 또는 로컬 편집기로 control-bootstrap.json의 필요한 역할 토큰을 확인해 화면에 입력합니다. 토큰을 채팅·이슈·화면 공유에 붙이지 마세요.

역할확인할 기능
author정책 초안·검토 제출·등록된 실행에 대한 예외 요청
approver다른 작성자가 제출한 정책·예외의 독립 승인
operator승인 정책 묶음 발급·보관 잠금 관리
auditor자기 기관·프로젝트의 실행·정책·증적 열람

역할은 합성 참조 신원입니다. 운영 OIDC·LDAP 연결이 아닙니다. 데모 이후 화면은 복구한 보관소를 사용하므로 보존 잠금된 합성 증적을 확인할 수 있습니다. 종료하려면 서버 터미널에서 Ctrl+C를 누릅니다.

GitHub Pages는 이 안내 사이트만 호스팅합니다. 검사 엔진·민원 API·관리 서버는 로컬 환경에서 실행합니다.

7. CI 적용을 준비하기

먼저 로컬 시험과 게이트 사용법을 확인하세요.

.runtime/reference-venv/bin/python -m unittest discover -s tests -p 'test_*.py' -q
.runtime/reference-venv/bin/python -m govcode_harness gate --help
  • ci/reference-gate.sh는 기본 입력 게이트, ci/reference-signed-gate.sh는 서명 정책 참조 예제입니다.
  • 신뢰한 전체 expected commit, 현재 HEAD, 증적 commit, 프로필과 receipt를 대조합니다. expected commit을 검사 대상 저장소의 사용자 파일에서 읽지 않습니다.
  • 서명 묶음·신뢰 목록·기관·프로젝트·최소 순번과 철회 자료는 검사 checkout 밖의 신뢰 경로에서 제공합니다.
  • 승인 예외는 정확한 commit·도구·정책·탐지 의미에 결합합니다. 오류·미분석·review를 예외로 통과시키지 않습니다.
  • 과거 archive 무결성 성공을 현재 commit의 통과 결과로 재사용하지 않습니다.

CI 예제는 비활성 상태입니다. 대상 저장소와 담당자를 정한 뒤 필수 검사와 보호 브랜치를 설정해야 실제 병합·배포를 막을 수 있습니다. 운영 중인 민원 요청을 차단하는 기능이 아닙니다.

8. 기관 파일럿을 준비하기

이 체크리스트는 준비 상태를 살펴보기 위한 도구입니다. 선택 결과는 저장되거나 전송되지 않으며 기관 승인 기록이 되지 않습니다.

권장 순서는 합성 데모 → 승인된 제한 저장소의 관찰 검사 → 독립 정답과 탐지·오탐·검토 부담 측정 → 기관 검토 후 필수 게이트 적용입니다. 일정·비용·성능을 미리 보장하지 않습니다.

법령상 확정 의무, 기관 정책, 예시 정책, 미확인 요구를 각각 기록하세요. 예시 정책을 운영 의무로 자동 승격하지 마세요. REG-LOG-008 등 미확정 법령 적용 항목은 원문·부칙·기준일 대조와 담당자 판단이 필요합니다.

문제 해결

증상조치

crypto·jsonschema 모듈 없음전용 참조 환경 설치가 완료됐는지 확인하고 .runtime/reference-venv/bin/python으로 실행합니다.

게이트 오류·commit 불일치신뢰한 expected commit·현재 HEAD·증적·프로필을 대조하고 수정 후 새 commit을 검사합니다.
